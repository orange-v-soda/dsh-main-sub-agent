# 技术说明

## 挂载位置

插件监听 `agent/pre-step`，这是一个瀑布事件，每一步模型请求前触发。监听器先 `await next()` 拿到上游决策，再决定是否往 `decision.messages` 里插一条消息。

插入位置是数组最前面，也就是所有用户消息和工具结果之前。这样规则在请求里的优先级最高，不会被后面的内容挤掉。

## 角色判定

```
agent.session?.header?.origin === 'subagent'
```

成立读 `sub.md`，否则读 `main.md`。路径按「全局 + 工作区」两段拼：

```
~/.dsh/agent-rules/<name>
<cwd>/.dsh/agent-rules/<name>
```

全局根目录可由 `DSH_HOME` 覆盖。两处都读不到就完全不注入，不产生空消息。

## 缓存

按 `mtimeMs:size` 作为版本戳缓存文件内容。文件没动就不重复读盘，改了立刻生效，不需要重启。

## 去重

插入的消息带 `source.kind = 'agent-rules'`。下一步如果这份文本已经在本轮消息里，就不再插第二份——比对的是 `source.kind` 加正文全文，不是路径。

## 失败策略

整段逻辑包在 try/catch 里，任何异常只 `ctx.logger.warn` 一次，然后原样返回上游决策。设计上它不能成为执行链路里的单点故障：规则读不到、路径非法、权限不足，都应该是「这步没注入」，而不是「这步失败」。

`signal.throwIfAborted()` 在组装完文本后调用一次，让被取消的请求尽快退出。

## 为什么不写会话日志

AGENTS.md 那类实现会把规则作为一条消息落进会话记录，于是要处理压缩改写、基线对账、导出可见性这些连带问题。这里选择不落盘，只做每步请求注入：

- 好处是压缩之后下一步自然补回，不需要补偿逻辑。
- 代价是导出会话记录时看不到这段规则。

这是有意的取舍，不是遗漏。
